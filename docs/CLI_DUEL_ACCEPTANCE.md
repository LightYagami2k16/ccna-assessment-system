## Scope and use

The local pilot adds **CLI Duels** to student, instructor and administrator navigation. A host selects exactly two students and configures a blank duel or loads a permitted practical as a copy through the full shared CLI Practical builder. Administrators may select across classes; instructors select through classes they currently own. Version3 supports up to12 routers, switches or PCs, physical topology links, the complete practical criterion catalog and quick presets. Class-wide races, teams, randomized values and academic grading remain outside this pilot.

The time limit defaults to the selected practical and can be set to 1–480 whole minutes. For newly created duels, the host opens directly into the spectator arena and students receive Enter arena invitations. Each student reserves their own assessment session on entry. The host explicitly starts a shared5-second countdown only after both players are active; play begins after both confirm they remain present at the countdown end. Older duels retain their earlier readiness flow. Instructions unlock after that countdown. The final minute has a visible warning. Host disconnection never pauses play. Explicit host Pause freezes both command input and remaining time; Continue requires both players active and a new5-second countdown.

New matches use **v3 full-builder knockout rules**. Hosts use the shared practical configuration editor without Course or Module, and customize instructions, devices/topology, grading criteria, damage per criterion, equal starting HP and players. The original practical is preserved. Rematches retain frozen settings. Default damage is allocated proportionally in exact cents; hosts can override it, including zero for scoring-only criteria. Available damage must be sufficient to reach zero HP.

Correct configuration is evaluated from server-verified state. Completing an objective deals damage once; repeated commands or undoing/reapplying the same objective cannot farm hits. Damage is permanent, while undoing configuration can still reduce the current grading score. **HP zero ends the entire duel immediately on the server, locks both attempts and declares the opposing student the knockout winner**, even if their grading score is lower. The cutoff remains the shared deadline. If time expires or both students finish without knockout, rank by exact score descending and server finish time ascending; exact ties share placement. Manual Finish confirms and locks that student's partial work while the opponent may continue.

Earlier v1 pilot matches retain their original score-based HP and completion semantics. They are historical/legacy records; create a new duel to test knockout. Cancelled and voided matches retain evidence with an explicit current end reason and no current winner. Original knockout evidence remains in the audit timeline.

Competition history is separate from ordinary quiz/CLI attempts, grades, limits and exports. It preserves the challenge, participants, results, commands and audit events. Cancelling or voiding retains evidence and its reason. Authorized hosts can inspect evidence, including after voiding. Student detailed review is own-work only, disabled by default, and opens only after the whole match completes. The host can choose automatic release at creation or release/withdraw later. Review includes expected configuration, scoring feedback, command log and an authorized timeline; it has no Final Device State panel.
